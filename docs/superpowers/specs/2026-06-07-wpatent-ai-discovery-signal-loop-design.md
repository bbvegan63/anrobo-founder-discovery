# W&Patent AI Discovery Signal Loop Design

> **Date:** 2026-06-07
> **Scope:** W&Patent publishing and external-signal sequence for Andrew Leung and OpenFor
> **Status:** Approved design

## Decision

Use a measured signal loop for W&Patent that prioritizes AI discovery through:

- one flagship onsite authority anchor
- one reinforcing LinkedIn signal from Andrew Leung
- one or two founder-useful follow-on W&Patent articles
- one low-friction OpenFor recognition ask after the first public trail exists

This loop should optimize for clearer answer-engine understanding of:

- `Andrew Leung`
- `W&Patent`
- `OpenFor member`
- startup patent strategy
- early founder patent decisions
- budget and prioritization judgment

## Why This Exists

W&Patent has already been repositioned live around Andrew-led founder advisory.
The next need is not random content volume.
The next need is a repeatable signal pattern that strengthens branded grounding and founder identity retrieval.

The loop should favor:

- entity clarity
- consistent wording across channels
- practical founder usefulness
- low-friction external recognition
- measurement after each meaningful step

The loop should avoid:

- publishing the whole draft queue at once
- mixing too many new URLs into the first authority push
- reverting to marketplace-first language
- asking OpenFor for recognition before Andrew and W&Patent have a clean public trail to point at

## Primary Goal

The first optimization target is `AI discovery`.

Expected first improvements should be:

- direct `Andrew Leung` naming
- direct `W&Patent` naming
- `wpatent.com` citations
- clearer OpenFor-linked identity understanding

This loop is not expected to produce immediate broad generic discovery wins on day one.

## Signal Loop

### Phase 1: Controlled Authority Signal

Keep the already-live flagship guide as the canonical authority anchor:

- `https://wpatent.com/startup-patent-strategy.htm`

Then publish one LinkedIn post from Andrew Leung that:

- links to that guide
- repeats the same founder-authority story
- makes `OpenFor member` context visible without exaggeration

This establishes:

- one canonical W&Patent source
- one external reinforcing source

### Phase 2: Onsite Depth

After the flagship guide plus LinkedIn post are live, publish follow-on W&Patent articles from the draft queue.

Do this one page at a time, not as a content burst.

Recommended second-wave order:

1. `drafts/wpatent/2026-06-06-post-provisional-vs-nda.md`
2. `drafts/wpatent/2026-06-06-post-provisional-and-poc-budget.md`

Hold for later:

- `drafts/wpatent/2026-06-06-post-draw-first-write-second.md`

Treat the draft pillar as supporting source material for this wave, not as the immediate next public page, because the live flagship guide is already the cleaner authority anchor.
If the pillar is later promoted out of `drafts/`, it must be retoned before publication so it matches the calmer founder-authority voice in this spec rather than leading with a "what practitioners won't tell you" hook.

### Phase 3: External Recognition Ask

After the first controlled public trail exists, request a low-friction OpenFor recognition surface.

Recommended first ask:

- simple member profile or member mention
- accurate public naming of Andrew Leung
- link to W&Patent or the flagship guide

Do not frame this as an SEO request.
Frame it as accurate peer recognition of a useful member resource for founders.

## Topic Focus

The near-term topic cluster should focus on:

- early founder patent decisions
- budget and prioritization

Remove commercialization from this immediate loop.
Commercialization can remain part of the broader W&Patent site, but it is not the next publishing focus.

## Channel Roles

### W&Patent

Role:

- canonical source
- founder-advisory proof surface
- home of the durable public guides

Primary near-term anchor:

- `startup-patent-strategy.htm`

Secondary near-term pages:

- the two selected draft-based follow-on articles

### Andrew Leung LinkedIn

Role:

- reinforcing external signal
- named-founder distribution surface
- practical founder takeaway channel

The first LinkedIn post should point to one page only:

- `startup-patent-strategy.htm`

### OpenFor

Role:

- third-party recognition surface
- ecosystem proof layer
- audience bridge to founders, cohorts, and alumni

OpenFor should not be the first publishing channel in this loop.
It should validate a story that is already publicly legible on W&Patent and LinkedIn.

## Message Rules

Across W&Patent, LinkedIn, and any OpenFor recognition surface, repeat one clean entity story:

- `Andrew Leung`
- `W&Patent`
- `OpenFor member`
- startup patent strategy for founders
- practical judgment on early decisions and budget prioritization

### Tone

Use a tone that is:

- founder-facing
- practical
- specific
- high-judgment
- calm and credible

Avoid:

- generic legal marketing
- marketplace-first framing
- vague partnership hype
- "what practitioners won't tell you" as the main house voice
- "what AI won't tell you" as the main house voice

### LinkedIn Post Rule

The first LinkedIn post should:

- reinforce Andrew as the named voice
- point to one canonical W&Patent page
- give one useful founder takeaway
- mention OpenFor member context accurately

### OpenFor Ask Rule

The first OpenFor ask should:

- request accurate public recognition
- position Andrew as a useful member resource
- stay low-friction and specific

## Publishing Order

Recommended execution order:

1. keep `startup-patent-strategy.htm` as the flagship anchor
2. publish one Andrew LinkedIn post pointing to it
3. log that post in W&Patent external signals
4. publish the first follow-on W&Patent article:
   - provisional vs NDA
5. log that publish event in W&Patent evidence
6. request a simple OpenFor member mention or profile link
7. rerun evidence and decide whether to continue with the next article

Do not promote the full W&Patent draft queue into public publication all at once.

## Measurement Rule

Use a measurement-led loop.

Before the first LinkedIn post goes live, capture a baseline read in founder-discovery so the loop has a clean before/after comparison.

Minimum baseline capture:

- log the current state in a dated W&Patent evidence note
- preserve the pre-loop score / roadmap interpretation already in founder-discovery
- run the non-Perplexity checks if they have not already been rerun since the June 7 site reposition:
  - Exa broad pack
  - local OpenAI OAuth diagnostic lane

After the LinkedIn post and first follow-on article are live:

- rerun the Exa broad pack
- rerun the local OpenAI OAuth diagnostic lane
- rerun the production compare later when `PERPLEXITY_API_KEY` is restored

Success should be evaluated first on:

- `Andrew Leung` naming
- `W&Patent` naming
- `wpatent.com` citations
- clearer OpenFor-linked identity retrieval

Do not assume success based on content output alone.

## Draft Handling Rule

The files under `drafts/wpatent/` are not the first signal push by themselves.
They are the follow-on content queue that supports the already-live flagship guide.

Do not promote or publish them in bulk.
Select one, publish it, log it, measure it, then decide the next move.

## Non-Goals

This loop is not for:

- full trilogy rollout as the first authority burst
- commercialization-first content
- broad marketplace revival
- generalized cohort playbook publishing on W&Patent
- external recognition requests before a controlled public trail exists
