# W&Patent Founder Project Pages Design

Date: 2026-06-08

## Context

The new W&Patent site is no longer a marketplace or listings board.

Its active public intent is:

- practical patent advice for founders
- Andrew Leung as the visible founder-facing voice
- support for OpenFor cohort founders and the broader founder public
- the clearest concrete service wedge: virtual marking

The older W&Patent site included a five-item startup and patent listings surface:

- `Points2Perks`
- `Tourist Aid`
- `Persona Album`
- `Sign Language Chat`
- `Dashing Robo`

Those pages no longer fit the current site story as marketplace listings, but they still suggest a useful question:

Should W&Patent support public pages about real founder projects without treating them as listings or virtual marking pages?

## Core Decision

Yes.

W&Patent may support **founder project pages** as a secondary content type.

These pages should:

- support real founders, startups, or projects
- explain the project in founder-readable language
- clarify technical angle and patent status accurately
- strengthen public entity context around Andrew Leung, W&Patent, startups, products, and inventions

These pages should **not** be treated as:

- marketplace listings
- sales opportunities
- virtual marking pages unless they actually satisfy virtual marking requirements
- a new primary service line

## Positioning Rule

The site should keep this split:

- `practical founder advice` = primary public value
- `virtual marking` = explicit service
- `founder project pages` = supporting public proof and context layer

This keeps the site aligned with the current W&Patent identity:

- Andrew Leung translates patent strategy into founder language
- W&Patent supports founders with practical judgment
- W&Patent can publish concrete project surfaces without becoming a listings board again

## What Founder Project Pages Are

A founder project page is a public page about a founder, startup, or invention context.

It should typically include:

- founder, startup, or project name
- short description of the product or idea
- technical angle in plain language
- patent status stated accurately
- one short explanation of why the invention matters

These pages are closer to:

- project briefs
- invention context pages
- founder proof pages

They are not:

- listing pages
- bid pages
- commercialization catalog entries
- legal opinion pages

## Patent Status Rule

Patent status must be stated carefully.

Recommended categories:

- provisional filed
- patent pending
- issued patent

The page must not imply issued-patent marking rights unless that is actually true.

Virtual marking should stay separate.

For a real virtual marking page, the safer practical rule is:

- issued patent
- real product or patented article
- accurate public association between the article and the issued patent number

So:

- issued patent + product may justify a virtual marking page
- pending application + product may justify a founder project page
- provisional or pending status alone does not justify a virtual marking page

## Discovery Role

Founder project pages help AI discovery differently from the pillar and cluster posts.

The advice posts help with:

- topic authority
- startup patent strategy queries
- Andrew Leung's point of view

Founder project pages help with:

- concrete named entities
- startup and project names
- product and invention descriptions
- patent-status associations
- Andrew / W&Patent relationship to real founder work

So the discovery value is real, but it is mainly:

- entity grounding
- citation context
- richer public founder-project graph

It is not mainly:

- direct service conversion
- generic topic ranking
- replacement for external signals

## Site Placement

Founder project pages should start under the support layer.

They should not begin as:

- a homepage hero item
- a top-level nav section
- a primary services card

Recommended initial placement:

- individual pages only
- linked selectively when relevant
- grouped later only if enough real examples exist

The main site path should stay:

1. `Home`
2. `Strategy`
3. `Services`
4. `About`

Founder project pages live underneath that structure.

## Service Rule

Founder project pages should **not** be added as a main named service now.

Reason:

- `virtual marking` is already the concrete service wedge
- adding founder project pages as a service now would blur the public offer
- the site would risk drifting back toward vagueness or marketplace energy

If real repeated demand appears later, they may become:

- a quiet advisory sub-offer
- a named support format
- or a grouped archive surface

But Phase 1 for this idea is simpler:

- treat them as a page type, not a service

## When To Create One

Create a founder project page only when:

- the founder or startup is real
- the facts are public or permissioned
- patent status can be stated accurately
- the page adds concrete founder-support value
- the page does not create confusion with virtual marking

Do not create one just to revive the old five-item list.

The old marketplace entries may be reused selectively as source material, but not restored automatically.

## First-Page Candidate Logic

If W&Patent tests this page type, the best first examples should be:

- real founder projects
- factually current
- patent status easy to state without overclaiming
- valuable to explain in founder language

They do not need to be OpenFor-only, but OpenFor-adjacent founders are a natural first cohort because they match the current site intention.

## Verification

If founder project pages are later implemented, verify:

- the page clearly reads as founder support, not a listing
- patent status language is accurate
- no virtual marking implication appears unless legally appropriate
- the page links naturally back into W&Patent's strategy or services surfaces
- the page strengthens entity clarity without reintroducing marketplace confusion
